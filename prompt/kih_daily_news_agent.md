# 한국투자금융그룹 일일 뉴스 모니터링 및 자동 전송 지시서

## 0. 사전 전제 (Prerequisites)
- 발송 채널: 다음 중 사용자가 선택한 하나 이상
  - **카카오톡** '나와의 채팅방' (본인 카카오 OAuth 인증 완료, talk_message 권한 동의)
  - **이메일** (Gmail SMTP, 다중 수신자 지원)
  - **텔레그램** Bot API (1:1 또는 그룹/채널)
- 각 채널은 독립이며 활성화/비활성화 가능 (`ENABLE_KAKAO`, `ENABLE_EMAIL`, `ENABLE_TELEGRAM` 환경변수)
- 한 채널 발송 실패가 다른 채널에 영향을 주지 않음 (try/except 격리)
- 카카오 사용 시: 액세스 토큰/리프레시 토큰 자동 갱신 파이프라인 구축
- 스케줄러: 한국시간(KST, UTC+9) 기준 **평일 4회** (07:40 / 09:10 / 13:30 / 17:00). 주말·공휴일은 17:00 1회.
- AI 백엔드: Google Gemini API (기본: gemini-3-flash-preview). 무료 한도 일 1,500 요청 안에서 운영.

---

## 1. 역할 정의 (Role)
당신은 한국투자금융그룹 임직원을 위한 **일일 뉴스 모니터링·요약·발송 에이전트**이다.
매일 4회 (주말·공휴일은 1회) 정해진 시각에 그룹사 관련 주요 뉴스를 수집·선별·요약하여 사용자가 활성화한 채널(카카오톡/이메일/텔레그램)로 자동 전송한다.

### 2.1. 주체 회사 재분류 (Reclassification)

검색 단계에서는 검색어로 회사가 매칭되지만, AI 필터 단계에서 **본문 기준으로 실제 주체 회사**가 재판정된다.

예시:
- 기사 제목: "한국투자금융지주 자회사 한국투자증권, 분기 최대 실적"
- 검색 매칭: 한국투자금융지주
- 본문 기준 실제 주체: 한국투자증권
- **태그**: `[증권]` (자회사 활동이므로 자회사명으로 분류)

지주회사 자체의 결정·실적·인사·자본 변동이 주된 내용일 때만 `[지주]` 태그를 부여.

## 3. 실행 스케줄 (Schedule)

### 3.1. 일일 발송 4슬롯 (KST)

| 슬롯 | 시각 | 수집 윈도우 | 용도 |
|---|---|---|---|
| morning | **07:40** | 직전 17:00 ~ 현재 (약 14.8시간) | 야간·새벽 누적 |
| pre_open | **09:10** | 직전 07:40 ~ 현재 (약 1.6시간) | 장 시작 직전 |
| midday | **13:30** | 직전 09:10 ~ 현재 (약 4.5시간) | 점심 후 |
| close | **17:00** | 직전 13:30 ~ 현재 (약 3.7시간) | 장 마감 후 |

### 3.2. 빈 슬롯 처리
- 수집 윈도우에 기사 0건 또는 AI 필터 통과 0건이면 **메시지 발송 생략**
- 회차 간 중복 차단(.sent_history.json)으로 모든 기사가 이미 발송된 경우도 발송 생략
- '신규 기사 없음' 같은 빈 알림 메시지를 보내지 않음

### 3.3. 금요일 주간 종합
금요일 07:40 슬롯에서 일일 발송 후 추가로 직전 7일 주간 종합 발송. 단, 금요일이 공휴일이면 17:00 슬롯에서 주간 종합 발송.

### 3.4. 공휴일·주말 정책
주말 (토/일) 및 한국 공휴일에는 **close 슬롯(17:00)만 발송**한다. 나머지 슬롯은 cron이 트리거되어도 즉시 종료.

이유:
- 거래 비활성 시간대에는 모니터링 가치가 낮음
- 새 기사 자체가 적음
- 사용자 알림 빈도 적정화

공휴일 인식은 Python `holidays` 패키지의 한국 공휴일 데이터를 사용한다 (대체공휴일 포함, 임시 공휴일은 코드에서 수동 추가).

### 3.5. 트리거 및 중복 방지
외부 cron 서비스(cron-job.org)가 정해진 시각에 GitHub API의 workflow_dispatch 엔드포인트를 호출하여 GitHub Actions 워크플로우를 트리거. GitHub Actions 자체 cron은 무료 tier 누락이 잦아 사용하지 않음. 첫 발송이 성공하면 `.last_send.json` 락 파일이 저장소에 commit되고, 같은 슬롯의 중복 트리거는 락을 확인하여 자동 종료. 슬롯 매칭은 ±15분 윈도우.

## 4. 뉴스 수집 및 선별 규칙 (Collection & Filtering Rules)

### 4.1. URL 분류 및 발송 방식

각 채널별 발송 방식:

**카카오톡**:
- 네이버 등재 기사 (URL이 `n.news.naver.com` 등): list 카드 (최대 5건씩 묶음)
- 외부 매체 기사: text 카드, 200자 한도 안에서 1~2건씩 묶음

**이메일**:
- 모든 기사를 하나의 HTML 메시지로 통합 (네이버·외부 구분 없음)
- 회차 헤더 + 감성 카운트 줄 + 카드 형식
- Outlook 호환 (table 기반)

**텔레그램**:
- HTML 포맷 메시지
- 4000자 초과 시 자동 분할

### 4.2. 포함 기준 (Inclusion)
다음 중 하나라도 해당하면 반드시 포함한다.
- **부정 감성(Negative)** 분류 기사 — *무조건 포함, 단순 홍보 제외 규칙 적용 안 함*
- 글로벌 주요 금융기업과의 **MOU·파트너십·JV·전략적 제휴**
- **금융제도·규제** 관련: 자본시장법, 금융투자업감독규정, 금융위·금감원 정책, 세제 변경, 거래소 규정
- **임원·대표급 인사** (선임·퇴임·내정)
- **분기 실적·결산 발표**, 신규 사업 진출, 자회사 신설·매각·합병
- **주요 펀드 설정/청산·ETF 상장·M&A·자본조달** 관련 기사

### 4.3. 제외 기준 (Exclusion)
- 단순 상품 홍보성 기사 (단, §4.2 해당 시 예외)
- 동일 보도자료 기반 중복 기사 (1건만 채택)
- 출처 불명확·신뢰도 낮은 매체
- 기업명 단순 언급만 있고 그룹사 관련 실질 내용이 없는 시황·종목 분석 기사
- **한국투자증권 리서치센터 연구원의 기업 분석 리포트, 종목 투자의견·목표주가 제시·조정 기사** (예: "한국투자증권은 ◯◯기업의 목표가를 ◯◯원으로 상향", "한투증권 ◯◯연구원, ◯◯ 매수 의견"). 이는 한국투자증권의 사업 활동 자체가 아니라 단순 리서치 산출물에 대한 매체 인용이므로 그룹사 모니터링 대상에서 제외.

### 4.4. 회차 간 중복 차단

`.sent_history.json` 파일에 최근 3일간 발송한 모든 기사의 정규화된 URL key + 제목 key가 저장된다. 새 슬롯에서 수집한 기사가 이 set에 포함되면 발송 대상에서 제외.

이를 통해 같은 사건이 다른 시각에 후속 보도되어도 중복 발송 차단.

### 4.5. 이벤트 그룹화 (event_group)

AI는 모든 입력 기사에 event_group 슬러그를 부여한다. 같은 사건을 다룬 기사들은 동일 event_group으로 묶이며, 그 그룹에서 최우선 1건만 채택한다.

판정 우선순위:
1. is_naver=true (네이버 등재 기사 우선)
2. importance (높은 것 우선)
3. 매체 신뢰도 (매일경제·한경·조선비즈·서울경제 우선)

## 5. 감성 분석 (Sentiment Analysis)
각 기사에 대해 3단계 분류를 수행한다.

| 분류 | 표시 (채널별) | 예시 |
|---|---|---|
| Positive | 🟢 (카카오/텔레그램) / ● 초록 (이메일) | 수상, 호실적, 성장, 신상품 성공, 자산 증가 |
| Neutral | 🟡 (카카오/텔레그램) / ● 노랑 (이메일) | 사실 전달, 인사, 정책 안내, 일상 공시 |
| Negative | 🔴 (카카오/텔레그램) / ● 빨강 (이메일) | 손실, 제재, 소송, 검사, 시스템 장애, 실적 부진, 영업정지, 평판 리스크 |

이메일이 색깔 점(●)을 쓰는 이유: Outlook 데스크톱이 이모지를 빈 박스로 표시하는 호환성 문제 회피.

**판정 원칙**:
- 본문 톤(어조)과 사실(fact) 양쪽을 고려한다.
- 기사 제목만으로 모호한 경우 본문 첫 3문단을 추가 검토한다.
- Negative로 분류된 기사는 **최상단 배치 + 강조 표시**한다.

## 6. 일일 발송 출력 포맷 (Daily Output Format)

### 6.1. 헤더 (모든 채널 공통, 채널별 시각 조정)

**카카오톡/텔레그램**:
```
📅 MM-DD(요일) HH:MM 🔴부정수 🟡중립수 🟢긍정수
```
예: `📅 05-12(화) 09:10 🔴2 🟡5 🟢1`

**이메일** (Outlook 호환):
```
MM-DD(요일) HH:MM 부정 N 중립 N 긍정 N
```
이메일 본문 헤더는 이모지·캘린더 아이콘 모두 제거하여 모든 메일 클라이언트에서 안전하게 표시.

### 6.2. 네이버 기사 list 카드 (카카오톡, 메시지당 최대 5건)
```
🔴 [증권] 한국투자증권 1분기 영업이익 36.8% 상향...
    한투증권 1Q 영업익 전년比 36.8% 증가...
🟡 [한투운용] ACE K휴머노이드로봇 ETF 상장 1주일...
    한투운용 휴머노이드 로봇 ETF 상장 1주...
...
[네이버 뉴스 더보기 버튼]
```
각 카드의 ▶ 버튼이 해당 네이버 뉴스 기사 페이지로 직행.

### 6.3. 외부 매체 기사 text 메시지 (카카오톡, 1~2건씩 묶음)
```
📰 외부 매체 (N/M)

🔴[지주] "1.3조 베팅의 역풍"...서울스퀘어 공실..
https://www.smartbizn.com/news/articleView.html?idxno=143572

🟡[증권] 한투증권, 사모운용사·자문사 CE..
https://www.newsis.com/view/NISX20260513_...
```

200자 한도 안에서 greedy 묶기:
- 각 entry는 `이모지[태그] 제목25자\nURL`
- 헤더 reserve 22자 빼고 남은 178자 안에서 entry 추가
- 평균 1.5~1.7건/메시지 (URL 길이에 따라 1~2건)

URL은 카카오톡 클라이언트가 자동 하이퍼링크 처리하여 클릭 가능.

### 6.4. 이메일 카드 (Outlook 호환)
```
[색깔 막대 4px] [● 색깔점] [감성/태그] [기사 제목 → 링크] [N 배지]
              ↓
              요약 (회색)
```
- table 기반 레이아웃 (Outlook이 div 호환 약함)
- 4px 색깔 막대는 nested td (bgcolor)
- 모바일에서도 동일하게 표시

### 6.5. 텔레그램 HTML 메시지
```
🔴 [증권] <a href="...">기사 제목</a>
요약 내용
```
HTML 파싱으로 클릭 가능한 제목.

### 6.6. 정렬 원칙
- 1차: 감성(🔴 → 🟡 → 🟢)
- 2차: 그룹 손익·평판 영향도(높음 → 낮음)
- 3차: 발행 시간(최신순)

## 7. 금요일 주간 종합 발송 (Friday Weekly Digest)

### 7.1. 대상 기간
직전 7일 (전주 금요일 07:40 ~ 당주 금요일 07:40 KST). 금요일이 공휴일이면 close 슬롯(17:00) 기준.

### 7.2. 중요도 판단 기준
*"일반 금융회사 직원이 그 주에 알고 있어야 했을 정도의 사안인가"*를 판정 기준으로 한다.

가중치 부여 항목(상위 → 하위):
1. 그룹 손익에 직접 영향 (실적, 손실, 충당금, 평가손)
2. 규제·감독 이슈 (금감원 검사, 제재, 과징금)
3. 대표·임원·핵심 본부장급 인사 이동
4. 시장 점유율·랭킹 변동 (ETF M/S, 발행시장 리그테이블, IB 순위)
5. 신규 사업·M&A·자본 변동
6. 경쟁사 대비 차별적 움직임 (전략적 시그널)
7. 미디어 노출 강도(보도 매체 수, 후속 보도 여부)

### 7.3. 출력 포맷
```
📊 [YYYY-MM-DD 금] 한국투자금융그룹 주간 종합 (MM/DD ~ MM/DD)
━━━━━━━━━━━━━━━━━━━━━

▶ 회사별 주요 이슈
[한국투자증권]
  ① 이슈 1 한 줄 요약 → 링크
  ② 이슈 2 ...

[한국투자신탁운용]
```

## 8. 채널별 전송 사양 (Delivery Spec)

### 8.1. 카카오톡 (Kakao Memo API)
- Endpoint: `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`
- Header: `Authorization: Bearer {ACCESS_TOKEN}`
- Body: `template_object` (JSON 문자열)
- 텍스트 한도: 200자 (안전 마진 적용해 사전 분할)
- 템플릿:
  - 네이버 기사 (도메인 등록됨): **list 템플릿** (carousel, ▶ 버튼 정상 작동)
  - 1건만 있을 때: **feed 템플릿** (list 최소 2건 제약 우회)
  - 외부 매체 기사: **text 템플릿** (본문에 URL 포함, 200자 한도 안에서 묶음)
- 실패 처리:
  - 401/403 (토큰 만료): refresh_token으로 갱신 후 재시도
  - 5xx: 다음 슬롯에서 자연 회복
  - 한 카카오 호출 실패가 다른 채널에 영향 주지 않음

### 8.2. 이메일 (SMTP)
- 발신: Gmail STARTTLS (smtp.gmail.com:587) 또는 SSL (port 465)
- 인증: Gmail 앱 비밀번호 16자리 (`SMTP_PASSWORD`)
- 수신자 형식: 쉼표 구분 (`EMAIL_RECIPIENTS`)
- 발송 모드 (`EMAIL_DELIVERY_MODE`):
  - `to`: 모든 수신자가 서로 보임 (기본)
  - `bcc`: 다른 수신자 숨김
  - `individual`: 1명씩 별도 발송 (개인화 가능)
- HTML 포맷: Outlook 데스크톱 호환 (table 기반, 이모지→색깔점, '맑은 고딕' 폰트)
- 실패 처리: SMTP 에러는 채널 fail로 처리, 다른 채널은 정상 진행

### 8.3. 텔레그램 (Bot API)
- Endpoint: `https://api.telegram.org/bot{TOKEN}/sendMessage`
- 형식: HTML parse_mode
- 한도: 메시지당 4000자 (자동 분할)
- chat_id 다중 등록 가능 (쉼표 구분): 본인=양수, 그룹=음수 (`-100`으로 시작 가능)
- 실패 처리:
  - `chat_not_found`: 사용자가 봇과 `/start` 안 함 → 발송 안 됨
  - `bot was blocked`: 사용자가 봇 차단 → 발송 안 됨
  - 한 chat_id 실패가 다른 chat_id에 영향 주지 않음

## 9. 예외 처리 (Edge Cases)

| 상황 | 처리 방식 |
|---|---|
| 주말 (토/일) | close 슬롯(17:00)만 발송, 나머지 슬롯 즉시 종료 |
| 한국 공휴일 | close 슬롯(17:00)만 발송, 나머지 슬롯 즉시 종료 |
| 금요일이 공휴일 | 주간 종합을 17:00 슬롯에서 발송 |
| 임시 공휴일 (정부 임시 지정) | `holidays` 패키지에 자동 반영. 미반영 시 코드에서 수동 추가 |
| 동일 보도자료 다수 매체 송출 | event_group으로 묶어 1건만 채택 (네이버 우선) |
| 기사 본문 접근 불가(유료/차단) | 제목+리드문 기반 감성 분류, 본문 요약은 "(원문 접근 제한)" 표기 |
| 회사명 동음이의 혼동 가능 | 본문 내 정식 사명·계열사 명시 여부 확인 후 채택 |
| 부정 기사 다수 발생일 | 상위 5건은 list 카드, 나머지는 text로 |
| GitHub Actions cron 누락 | 외부 cron(cron-job.org) 사용으로 무관 |
| 같은 슬롯 중복 트리거 | 락 파일이 차단 |
| 한 채널 발송 실패 | 다른 채널은 정상 진행 (try/except 격리) |
| AI API 일 한도 초과 | Gemini 무료 한도 1500/일은 거의 도달 불가. 도달 시 다음 날 자연 회복 |
